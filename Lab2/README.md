Откройте именно папку D:\1Study\!3Course\СПО\Lab1.
В меню «Терминал → Выполнить задачу» выберите «Запустить парсер».

Из PowerShell в папке проекта:

Уже собранный build\GroovyGilb.exe можно открыть двойным щелчком.

## Файлы

- sample.groovy — анализируемая программа, 92 строки, включая поясняющий комментарий.
- gilb.hpp — лексер, структурный парсер, расчёт метрик.
- main.cpp — окно Windows, загрузка и редактирование кода, вывод метрик и ветвлений.

Код можно редактировать в окне. «Анализировать» обрабатывает текущий текст
редактора и выводит три метрики, число операторов N и список ветвлений
с номерами строк, названиями конструкций и уровнями вложенности.

в VS Code, выберите файл повторно.

## Подготовленная программа

Простой расчёт покупки в магазине: исправить ошибочные цены, сложить
стоимость товаров, определить скидку, рассчитать оплату и сдачу.
Подробное объяснение каждого этапа написано в комментарии в начале sample.groovy.
correctPrice исправляет отрицательную цену; discountAmount вычисляет скидку.
Есть классический for, for-in, while, do-while, if/else и switch внутри if.
Во втором case находится вложенный if/else. Есть break, continue и return.
Для самого парсера Java и Groovy не требуются.

Ожидаемый результат для заданных данных:
- цены: [120, 80, 0, 200, 50];
- платных товаров: 4;
- первый товар от 100 рублей: 120;
- сумма без скидки: 450;
- скидка: 10%, то есть 45 рублей;
- к оплате: 405;
- пять взносов по 100 рублей: внесено 500;
- сдача: 95 рублей.

## Правила расчёта

Основание: страницы 3–5 предоставленного PDF и уточнения преподавателя.

CL — число условий: каждый if, for, while, do-while и каждый case дают 1.
Завершающий while у do-while не считается вторым циклом.
Селектор switch, else и default не добавляют условий.
Несколько сравнений, объединённых && или || внутри одного условия,
не превращаются в несколько if.
Вложенность одиночного условия — 0, вложенного в него — 1 и так далее.
Блоки функций и обычные фигурные скобки сами по себе вложенность не повышают.
Тела разных функций анализируются независимо; CL и N суммируются,
CLI — наибольший уровень среди всего исходного файла. Вызовы не разворачиваются.

Для switch с k метками case создаётся цепочка k условных операторов.
При внешнем уровне d метка case с номером i имеет уровень d+i-1.
Условия внутри тела этого case начинаются с уровня d+i.
Вложенные условия одного case не влияют на уровень следующих case.
Четыре case у внешнего switch: CL=4, CLI=3.
У switch внутри внешнего if эти case имеют уровни 1, 2, 3, 4.

default сам ничего не прибавляет. Если в его теле написан if/цикл,
этот настоящий оператор учитывается в контексте последнего else цепочки:
его уровень d+k. Отсутствие default не уменьшает число условий case.
Последовательно записанные метки case учитываются по одной на метку.
break и fall-through не добавляют условий; это структурная метрика,
не анализ достижимости и не моделирование выполнения программы.

cl = CL / N.

Для N выбран подсчёт операторов ИСХОДНОГО Groovy:
- одно объявление переменных, присваивание, вызов, return, break, continue,
  throw или assert — один оператор;
- if, каждый цикл и весь switch — по одному оператору, плюс операторы их тел;
- инициализация, проверка и изменение счётчика внутри заголовка for входят
  в один оператор for и отдельно в N не добавляются;
- case, default, else, сигнатуры функций, скобки, комментарии и пустые
  разделители не считаются отдельными операторами;
- преобразование switch в цепочку if применяется к CL и CLI;
  знаменатель N остаётся числом операторов исходного кода;
- выражение a = b + c является одним оператором, а не тремя лексическими
  операциями; вычисления аргументов вызова отдельно не считаются.

При пустом файле выводятся нули, включая cl=0 (деление на ноль не выполняется).
PDF не задаёт отдельные правила декомпозиции операторов Groovy;
используемое соглашение N приведено выше.

## Контрольные значения sample.groovy

CL = 14: шесть if, четыре цикла и четыре case.
N = 56.
cl = 14 / 56 = 0,25.
CLI = 4: четвёртый case внутри внешнего if.
if во втором case имеет уровень 3.
Вводный комментарий не влияет на метрики.

## Границы учебного парсера

Разбирается процедурный код с указанными управляющими конструкциями,
функциями уровня скрипта, выражениями и списками.
Поддерживаются тела без фигурных скобок, вложенные switch, for-in и for с :,
комментарии // и /* */, обычные и тройные строки, slashy/dollar-slashy строки,
разделение операторов точкой с запятой и переводом строки,
переносы внутри круглых/квадратных скобок и после бинарного оператора.

Это структурный анализатор, не полный компилятор Groovy: типы, существование
переменных и методов, совместимость выражений и все ошибки языка не проверяются.
Не поддерживаются классы, импорты, аннотации, closures, try/catch/finally,
switch-выражения со стрелками, тернарный оператор, Elvis, safe-index
и выражения интерполяции внутри строк. Для этих конструкций выдаётся ошибка;
в примере они не используются. Сложные неоднозначные формы динамического
Groovy вне указанного синтаксиса не следует использовать для расчёта.
Короткая интерполяция имени переменной в строке не содержит ветвлений.
Регулярные литералы распознаются в обычных позициях выражения (например,
после =); разбор не заменяет полный контекстный лексер Groovy.
